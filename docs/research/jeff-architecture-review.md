# JEFF architecture review and application plan

Reviewed 2026-10-07 at immutable commit [`3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0`](https://github.com/firelex/jeff/tree/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0), using a read-only local clone. This is source inspection, not a reproduction of released weights, training or hardware measurements. No JEFF weights were downloaded or executed, and no training or serving process was launched for this research.

JEFF's useful lesson for UL LayaGo is a verified shared base with explicit task adapters, independent calibration and disciplined data audits. Its released decoder weights and LoRA matrices are incompatible with Laya's bidirectional encoder/marker architecture. DelayLama should adopt the lifecycle and finite-decision interface while preserving source proofs and human review.

## What the implementation does

JEFF's Qwen path takes the final prompt-token representation, projects it through a bias-free 255-row readout and masks unused options before softmax. Answer-code rows initialize from the pretrained language-model output embedding; each code must be one token and remain one token after the chat prefix. There is no autoregressive answer generation or JSON extraction for this decision. This remains full prompt processing, rather than a free decision merely because only one output position is scored. [Decision model](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/model.py#L145).

The repository also implements a ModernBERT cross-encoder: every option becomes a separate `(instructions+state, option)` pair, scored from its first-token representation. It batches the pairs but repeats state processing per option. That differs from Laya's joint sequence with option markers. JEFF explicitly rejects encoder architecture in its LoRA attachment path. [Encoder](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/encoder.py#L24), [LoRA attachment](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/lora.py#L92).

UL LayaGo currently loads a frozen ModernBERT/mmBERT encoder, type embeddings, optional head transformer layers, a marker scorer and an act head. Its trainer fits the zero-transformer-layer scorer/act head from cached encoder states; complete pretrained two-layer heads remain inference-only. These are existing capabilities, not JEFF-inspired encoder LoRA, full-head RLCD or dual-encoder InfoNCE. [Current training contract](../training.md), [head](../../laya/head.go), [trunk identity](../../train/trunk.go).

| Concern | JEFF implementation | Appropriate LayaGo transfer |
|---|---|---|
| Shared model | One decoder with selected LoRA attention/MLP updates | One verified frozen encoder with separately selected immutable head artifacts |
| Trainable adapter | LoRA matrices **and full decision readout** | Existing scorer/type/act parameters; encoder LoRA requires a separate backward/numeric design |
| Input-dependent states | Causal full-prompt forward | Joint bidirectional states; cache only an identical complete encoded sequence |
| Calibration | Adapter temperature and option limit | Retain each head's task/option-bucket temperatures and independent selective thresholds |
| Selection | Explicit adapter name; unknown names rejected | Explicit artifact/task selection; no silent fallback to another head |

## Versions, caching and serving

V1.3 freezes `live-last` for object states: instructions, earlier fields and options precede the final changing field. Plain text/list states retain state-first; empty objects fail. The documentation records a quality regression when long text moved after options. Earlier artifacts lacking a layout use state-first. V1.3 and v1.2 adapters must not be interchanged. [Frozen format](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/docs/v1.3-request-format.md).

The layout enables causal prefix reuse in principle. The inspected PyTorch forward sets `use_cache=False`; MLX serving calls the model with the complete token list and no prefix-cache argument. This repository therefore does not demonstrate a deployed prefix-cache speedup. Bidirectional Laya cannot reuse an earlier prefix's final representations after changing later content without altering attention semantics. An opt-in bounded whole-sequence cache can instead key exact token IDs, frozen base, tokenizer/renderer and numeric kernel; mutations and cross-adapter input changes must miss. [PyTorch forward](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/model.py#L231), [MLX forward](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/mlx_backend.py#L131).

JEFF adapters include their readout, temperature, layout, option limit and exact backbone-weight hashes. Serving also checks model revision, architecture and answer vocabulary. Strengthen this pattern locally by sealing tokenizer and encoder configuration, sequence budgets, head architecture and numeric path too. Do not identify an adapter only by a filename or directory. JEFF serializes adapter selection and inference under a lock; busy requests get 529 after their configured wait. Shared mutable selection is safe only under that invariant. Immutable per-request Laya heads avoid a global active-adapter race. Input beyond the configured token bound is rejected rather than clipped. [Compatibility and adapter set](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/lora.py#L151), [server](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/server.py#L101).

## Training lessons that transfer

The actual objective is soft-target cross-entropy. Choice order is shuffled with the target distribution remapped; ordinal score levels stay ordered. Optimizer state uses float32 CPU master parameters with AdamW and copies updates back to the model. Training records dataset/code/initial-artifact identities and restores optimizer/cursor/RNG state only for a matching resume. Its CUDA synchronization and dependency path are not an Apple MLX training recipe. [Targets and augmentation](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/train.py#L266), [training loop](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/train.py#L805), [optimizer](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/optim.py#L22).

Temperature is fitted on a separate hard-labelled calibration fold. Checkpoint selection minimizes uncalibrated development NLL, then calibrated accuracy, subject to optional ECE/Brier reference guards. The release shell recipe scores its final checkpoint, so selected-development and published-final artifacts must not be conflated. JEFF's API choice `confidence` is a chance-adjusted top probability; evaluation confidence is the actual top probability. Preserve Laya's calibrated probability and act/escalation semantics rather than mapping these fields by name. [Calibration/selection](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/evaluate.py#L205), [API answer](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/model.py#L101), [release recipe](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/scripts/train_all.sh).

The adapter kit offers directly useful engineering checks: family-held-out splitting, exact/near source leakage, option position/length predictors, metadata-generation-round shortcuts and surface-only classifiers. For contracts, a family must include the original, translations, paraphrases, excerpts and counterfactuals. Keep independently authored locked tests outside both fitting and replay. A shortcut report cannot validate labels. Replay is optional and requires one's own provenance-qualified data; the documented shipped sample is illustrative. [Kit guide](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/examples/adapter-kit/README.md), [leak checker](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/kit/leaks.py#L137).

## Practical application and acceptance

1. Share the verified frozen Laya encoder, attach independently validated head artifacts and expose explicit selection. Prove A→B→base→A equivalence to independently loaded models, concurrent isolation, wrong-base/tokenizer/layout rejection, unknown-name rejection and each artifact's own calibration. Unknown nonnull adapter metadata must fail consistently in training and serving loaders.
2. Add a bounded opt-in exact-sequence state cache only after parity and mutation tests. Measure unique-input misses, repeated-input hits, eviction, bytes retained and p50/p95 under concurrency. Frozen states cannot survive encoder fine-tuning or different tokenization.
3. Begin DelayLama in shadow mode with finite nomination tasks: own prerequisite versus proposed/other arrangement; supplied quotation support versus contradiction/insufficient evidence; or next evidence-review stage. Supply current original IDs/SHA/spans, own paragraph and explicitly resolved references. Preserve model probabilities, artifact identity and request capture as a separate sidecar. Learned votes cannot locate quotations, assert referent bridges, accept graph types, or turn record absence into nonfulfillment.
4. Build new adjudicated EN/FR/DE stories with close actor/ID/instrument/negation contrasts and independent insufficient-evidence labels. Existing observed q8/q9 examples and development controls are known development evidence, not fresh held-out gold. Compare majority, existing pretrained Laya, adapted Laya and the LLM on identical frozen stories; report false support and coverage by language/task, not just overall accuracy.

## Performance and provenance limits

The README reports 22 ms GPU/28 ms MLX for short base decisions and 0.25 s mean for a separate adapter comparison. Different token lengths, hardware, means/medians and request paths make these unsuitable as DelayLama speed predictions. V1.3's reported legal-clause zero-shot result falls from v1.2's 66.0% to 7.4%, while its adapter reaches 83.6%; specialization is not a guaranteed stronger universal base. These are authors' measurements, not reproduced here. [Reported measurements](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/README.md), [timing harness](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/latency.py).

Use real contract token distributions and include tokenization, source-window preparation, adapter switching, queueing, JSON/provenance capture, graph retrieval and LLM fallback in local timings. Reversed-option averaging is two forwards, not one. Cached-head training throughput does not measure encoder or API inference. The released trained context is bounded; increasing a server limit does not establish long-contract correctness.

Code has an MIT licence, with both JEFF and AutoJev notices. Weight/dataset terms are separate: the README identifies noncommercial restrictions for some adapters and source-specific terms for others. The training sources document is explicitly v1.2-era; raw training data is not published. Exact release retraining and the external reference-app/JEFF-Code results cannot be reproduced from this clone alone. The kit's adapter-loading prose is also older than `models.load_decision_model`, which now supports adapter folders containing decision metadata. Check executable paths and each asset's own current licence before reuse. [Licence](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/LICENSE), [data sources](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/docs/data-sources.md), [current loader](https://github.com/firelex/jeff/blob/3720e7c66d73b79a6e90189f3d5b0d6ecf03ddc0/src/jeff/models.py#L45).

Its card confirms a 9,895-row, 100-label LEDGAR test and an additional 7,357-row novel test not supplied in that repository. The pinned card says the updated QA report and row-reconstruction script are pending, and the replay mix's benefit was not measured. It does not validate the later v1.3 cascade numbers. Its large model must produce JSON, while JEFF directly scores option logits; malformed large-model responses count as wrong. This is a useful application comparison, not an isolated backbone comparison. [Pinned evaluation method](https://github.com/firelex/jeff-reference-app/blob/4e86bc110a3fa1be3bea688e82271f7dc60a77b9/README.md).
